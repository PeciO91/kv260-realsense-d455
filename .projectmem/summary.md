# projectmem - KV260_Camera

_Last updated: 2026-10-19_

## Project purpose
Intel RealSense D455 RGB/depth capture and INT8 person/face detection on AMD/Xilinx Kria KV260. Python utilities provide camera diagnostics and browser previews; C++17 DenseBox/YOLOv26 applications run on the board's DPU and deliver annotated MJPEG or H.264/RTP video plus independent Redis face status to a Raspberry Pi.

## Decisions
- Existing deployment target is Kria KV260 with Intel RealSense D455 on Xilinx/PetaLinux 2022.2; Python 3.9 scripts provide camera diagnostics/previews and native C++17 applications provide DPU inference. [docs/realsense-rsusb.md; camera/; inference/]
- Use source-built librealsense 2.58.4 with FORCE_RSUSB_BACKEND=ON and Python bindings on the KV260: the native V4L2/UVC backend caused a kernel Oops during pipeline.stop() on Xilinx 2022.2. [docs/realsense-rsusb.md; requirements.txt]
- YOLOv26 uses Vitis AI 3.0 XIR/VART RunnerExt directly with an externally compiled INT8 xmodel: one DPU child subgraph, split one2one box/class tensors paired by stride-8/16/32 spatial shape, two classes (Person/Human face), REG_MAX=1 LTRB decoding, no NMS. [inference/yolov26_realsense_core.cpp; inference/yolov26_common.hpp]
- YOLO browser and Pi applications share yolov26_realsense_core.{hpp,cpp} and yolov26_common.hpp for camera profiles, RGB letterboxing (INTER_LINEAR, border 114), INT8 LUT quantization, DPU execution/decoding, annotations, telemetry, and sparse calibrated depth. [inference/yolov26_realsense_core.hpp; inference/yolov26_realsense_core.cpp; inference/yolov26_common.hpp]
- Native live detection uses a calibrated 5x5 sample grid over the central 35% of each box to map color ROIs into raw Z16 depth and take the median, avoiding full-frame alignment; default color is 848x480@30 with the smallest same-FPS depth profile (424x240 on the documented camera). [inference/yolov26_realsense_core.cpp; inference/live_densebox_realsense.cpp]
- YOLO live processing separates main-thread capture/DPU/depth from renderer-thread overlay/encoding/sending with a capacity-1 latest-frame handoff; replacing pending frames bounds latency instead of queuing a backlog. Browser output remains HTTP MJPEG; Pi output uses native GStreamer appsrc. [inference/live_yolov26_realsense.cpp; inference/live_yolov26_rpi.cpp; inference/yolov26_realsense_core.hpp]
- Pi integration sends annotated H.264/RTP over best-effort unicast UDP (default 5000, payload 96, MTU 1200) and independent Redis Pub/Sub status (default 6379/channel face_detection); status is not frame-paired, emits {"face_detected":true|false} only for fresh successful inference, and stale/unavailable means silence rather than false. [inference/yolov26_rpi_control.hpp; inference/yolov26_rpi_transport.cpp; scripts/mock_yolov26_sender.py]
- Native builds use per-application POSIX shell scripts and g++ -std=c++17 -O2 -Wall -Wextra with pkg-config (no CMake/project-wide build): DenseBox links Vitis AI facedetect, YOLO links VART/XIR, and the Pi sender adds GStreamer app/video plus hiredis. [scripts/build_densebox_realsense.sh; scripts/build_live_densebox.sh; scripts/build_live_yolov26.sh; scripts/build_live_yolov26_rpi.sh]
