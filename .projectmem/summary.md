# projectmem - KV260_Camera

_Last updated: 2026-10-29_

## Project purpose
Intel RealSense D455 RGB/depth capture and INT8 person/face detection on AMD/Xilinx Kria KV260. Python utilities provide camera diagnostics and browser previews; C++17 DenseBox/YOLOv26 applications run on the board's DPU and deliver annotated MJPEG or H.264/RTP video plus independent Redis face status to a Raspberry Pi.

## Decisions
- Existing deployment target is Kria KV260 with Intel RealSense D455 on Xilinx/PetaLinux 2022.2; Python 3.9 scripts provide camera diagnostics/previews and native C++17 applications provide DPU inference. [docs/realsense-rsusb.md; camera/; inference/]
- Use source-built librealsense 2.58.4 with FORCE_RSUSB_BACKEND=ON and Python bindings on the KV260: the native V4L2/UVC backend caused a kernel Oops during pipeline.stop() on Xilinx 2022.2. [docs/realsense-rsusb.md; requirements.txt]
- YOLOv26 uses Vitis AI 3.0 XIR/VART RunnerExt directly with an externally compiled INT8 xmodel: one DPU child subgraph, split one2one box/class tensors paired by stride-8/16/32 spatial shape, two classes (Person/Human face), REG_MAX=1 LTRB decoding, no NMS. [inference/yolov26_realsense_core.cpp; inference/yolov26_common.hpp]
- YOLO browser and Pi applications share yolov26_realsense_core.{hpp,cpp} and yolov26_common.hpp for camera profiles, RGB letterboxing (INTER_LINEAR, border 114), INT8 LUT quantization, DPU execution/decoding, annotations, telemetry, and sparse calibrated depth. [inference/yolov26_realsense_core.hpp; inference/yolov26_realsense_core.cpp; inference/yolov26_common.hpp]
- Native live detection uses a calibrated 5x5 sample grid over the central 35% of each box to map color ROIs into raw Z16 depth and take the median, avoiding full-frame alignment; default color is 848x480@30 with the smallest same-FPS depth profile (424x240 on the documented camera). [inference/yolov26_realsense_core.cpp; inference/live_densebox_realsense.cpp]
- YOLO live processing separates main-thread capture/DPU/depth from renderer-thread overlay/encoding/sending with a capacity-1 latest-frame handoff; replacing pending frames bounds latency instead of queuing a backlog. Browser output remains HTTP MJPEG; Pi output uses native GStreamer appsrc. [inference/live_yolov26_realsense.cpp; inference/live_yolov26_rpi.cpp; inference/yolov26_realsense_core.hpp]
- Pi integration sends annotated H.264/RTP over best-effort unicast UDP (default 5000, payload 96, MTU 1200) and independent Redis Pub/Sub status (default 6379/channel face_detection); status is not frame-paired, emits {"face_detected":true|false} only for fresh successful inference, and stale/unavailable means silence rather than false. [inference/yolov26_rpi_control.hpp; inference/yolov26_rpi_transport.cpp; scripts/mock_yolov26_sender.py]
- Native builds use per-application POSIX shell scripts and g++ -std=c++17 -O2 -Wall -Wextra with pkg-config (no CMake/project-wide build): DenseBox links Vitis AI facedetect, YOLO links VART/XIR, and the Pi sender adds GStreamer app/video plus hiredis. [scripts/build_densebox_realsense.sh; scripts/build_live_densebox.sh; scripts/build_live_yolov26.sh; scripts/build_live_yolov26_rpi.sh]
- User approved correcting projectmem's contradictory instruction templates: summary.md remains generated and events.jsonl append-only via MCP; PROJECT_MAP.md and plan.md are authored files editable after precheck, with decisions/context logged separately and summary regenerated after map-purpose changes. Session must reload corrected MCP instructions before exercising the authored-file exception. [AGENTS.md; CLAUDE.md]
- YOLO defaults raised to confidence 0.30 and max-detections 50; added InferenceOptions.show_depth_roi (default false, gates only the blue depth-ROI rectangle) and show_confidence (default true, hides only the numeric score while keeping class label and distance/N/A). draw_detection_annotations now takes const InferenceOptions&; both YOLO apps pass their options. Browser app gained --show-depth-roi/--show-confidence/--telemetry true|false (telemetry default false, gating SystemMonitor polling, draw_telemetry, log_telemetry and PerformanceMonitor recording); Pi sender parser gained the same show-* flags with strict validation. DenseBox and mock sender unchanged. [inference/yolov26_common.hpp; inference/yolov26_realsense_core.cpp; inference/live_yolov26_realsense.cpp; inference/yolov26_rpi_control.cpp; inference/live_yolov26_rpi.cpp]
- YOLOv26 HDMI display implemented as a third output alongside MJPEG/Pi: inference/live_yolov26_hdmi.cpp renders on the local X desktop (fullscreen default) via a yolov26_hdmi_display.{hpp,cpp} XOpenDisplay+cv::imshow adapter with aspect-fit black canvas, dependency-free yolov26_hdmi_control.{hpp,cpp} CLI/geometry, and a new nonblocking LatestFrameHandoff::try_pop so the GUI loop stays responsive. --test-pattern produces labelled synthetic frames (NO CAMERA / NO INFERENCE) through the same handoff without touching camera/model; X display is validated before model/camera init; help is fully offline; real camera+DPU run left to the user. LatestFrameHandoff blocking wait_pop behavior unchanged for existing callers. [inference/live_yolov26_hdmi.cpp; inference/yolov26_hdmi_control.cpp; inference/yolov26_hdmi_display.cpp; inference/yolov26_realsense_core.hpp; scripts/build_live_yolov26_hdmi.sh; scripts/run_live_yolov26_hdmi.py]
- Fullscreen HDMI now upscales frames aspect-fit to screen (fit_image into screen dims, reused scaled_ Mat, no canvas/copyTo) and sets app-wide black GTK background via GtkCssProvider + gtk_style_context_add_provider_for_screen in HdmiDisplay ctor — replaces the removed letterbox canvas at a fraction of its cost. Windowed mode shows native size. Build links gtk+-3.0 (dev packages present on PetaLinux image). Verified on board: 848x480 -> 1024x580 fills width, black bottom band (xshot-verified), real run ~29-30fps, e2e ~75ms, cpu ~78%. Prior numbers: native-imshow ~30fps/50ms/50%cpu, canvas-letterbox ~24fps/100ms/78%cpu.
- KMS renderer: ZynqMP DPSUB has no scaler — both enabled layers must share source size (driver logs 'Layer width:height must be 1920:1080', 634 times on the board, and skips video enable). KmsDisplay now allocates mode-sized scanout buffers, composes/resizes in software (detail::compose_kms_frame), presents with src==dst==full mode via drmModeSetPlane, selects planes by type with DRM_CLIENT_CAP_UNIVERSAL_PLANES, uses checked legacy SetCrtc (fake atomic branch removed), and saves/restores graphics alpha/g_alpha_en. New --kms-plane primary|overlay (default primary). Hardware scaling is not claimed. [inference/yolov26_kms_display.cpp]
- KMS fullscreen default scaling is now nearest-neighbour done at 16/32-bit word level after converting at native size (--kms-scaling nearest|linear, kms only); linear kept for quality A/B. Board real-camera 30s runs, primary plane, fullscreen: nearest fps 29.8, e2e 45 ms, cpu 32% (wait 2.8 / draw 1.5 / show 7.3 ms); linear fps 28.7, e2e 80 ms, cpu 65% (wait 13.3 / show 30.8 ms); windowed e2e 39 ms, cpu 24%. HDMI telemetry now reports wait (handoff), draw (annotations+overlay) and show (render) means. Visual quality of nearest awaiting user judgement. [inference/yolov26_kms_display.cpp]
